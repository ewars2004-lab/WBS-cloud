# Cursor Automation（定期バッチ）

WBS更新チームの **平日 10:20・19:00 JST** 実行用メモ。

## スケジュール（JST）

| 回 | cron（UTC想定: JST-9） | 用途 |
|---|---|---|
| 朝 | `20 1 * * 1-5` | 10:20 JST |
| 夕 | `0 10 * * 1-5` | 19:00 JST |

※ Cursor Automation のタイムゾーン設定に合わせて調整すること。

## プロンプト例（Automation に貼る）

```
あなたは WBS更新チーム のオーケストレータです。

1. skills/wbs-update-workflow を読み、定期バッチモードで実行する。
2. 新NagiWBS の対象行（進行中 or 完了根拠Slackが空）を Planner が切り出す。
3. Slack調査 → WBS更新案 → Verifier → 反映可なら Sheets に書き込む。
4. 曖昧な行は Nagi の自分DMにスレッドリンクと「これはどういう状態ですか？」を送り、WBSは触らない。
5. バッチ終了後、Nagi DM にサマリー（更新件数・要回答件数・スキップ件数）を送る。

触ってよいのは 新NagiWBS のみ。F列（完了期限）は絶対に編集しない。
案件別スプレッドシート（5W1Hタブ・総合テスト・Figma）は触らない。
```

## DM返答トリガー（別 Automation）

Nagi が曖昧質問に返答したとき用。

```
あなたは WBS更新チーム のオーケストレータです。DM返答モードで実行。

1. Nagi の最新返答と、直前に送った「これはどういう状態ですか？」メッセージを紐づける。
2. 該当 WBS 行だけ Slack調査（必要なら）→ 更新案 → Verifier → 反映。
3. Nagi DM に「反映しました: {案件} / {工程}」と短く返す。
```

Slack トリガーは Nagi の自分 DM を指定。Automations エディタでチャンネルを選ぶ。

## 手動実行

チャットで `WBS更新チームでバッチ実行` でも同じフロー。
